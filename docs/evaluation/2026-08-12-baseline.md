## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| プロジェクト名 | Open Civil Site Risk Checker（工事候補地リスクチェッカー） |
| 目的 | 土木・建設工事の候補地初期調査を、公開データ横断取得＋確認優先度（A〜D）で支援する |
| 利用者 | 現場・本社・経営層・協力会社（約600名組織の DX 部門 7 名が運用） |
| 業務課題 | 候補地ごとの災害・河川・道路・施設・気象情報の収集工数大、根拠のない判断、調査の属人化 |
| 提供価値 | 一次情報への根拠リンク付き調査メモ、断定しない判定表現、調査の再現性 |
| 完成段階 | Phase 2（MVP＋KSJ 空間検索＋AI ブローカー）実装済み、Phase 3 機能（JMA 警報）一部実装 |
| 運用段階 | 本番稼働中（`https://riskchecker.mirai-dx-platform.com/`・Cloudflare Access 認証・Neon DB・systemd） |

**総合判定: 条件付き利用可（Conditional）**

本番稼働と初期調査の現場適用は可能。ただし 600 名規模の本番運用には「案件台帳のサーバ永続化・RBAC・監査」「ハザードの自動判定」「復元演習」「Alerting」「IdP 確定」を条件とする。

## 3. 強み（15 件）

1. 国・公的機関の一次情報（KSJ・地理院・気象庁・Open-Meteo・OSM）を横断取得
2. 確認優先度 A〜D と「断定しない」表現ルール（安全/危険/施工可否を言わない）
3. 全 Finding に根拠データ ID・出典・取得日時を紐付け
4. 疑似取得ログ廃止（`not_attempted` / `visual_only` で実通信の有無を誠実に記録）
5. Cloudflare Access JWT を edge と origin の両方で検証（#70/#240 対応）
6. CSP・X-Frame-Options 等のセキュリティヘッダ全応答付与
7. AI キーのサーバー側管理・固定窓レート制限・同時実行上限
8. 調査データをサーバ保存しない設計（発注前情報の漏えい対策）
9. 依存ゼロ静的サーバ＋same-origin プロキシ（SSRF・資格情報転送防止）
10. systemd/Docker 両対応・watchdog による死活監視と Issue 集約
11. Neon PITR＋ハッシュ付きカスタム形式バックアップスクリプト
12. CI（frontend/backend/security）＋Dependabot＋audit ゲート
13. テスト資産（vitest/smoke/server/pytest/NFR ベンチマーク）
14. README・要件・仕様・運用文書の整合管理（v1.3 同期済み）
15. 低コスト運用（OSS・公開データ・serverless DB・利用量制御）
